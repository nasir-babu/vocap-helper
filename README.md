## 🌟 নতুন ফুলস্ট্যাক ফিচারসমূহ (New Fullstack Features)

### ১. 📦 ব্যাচ সেশন কার্ড (Batch Card Architecture)
* হোম ভিউতে টেক্সট পড়ার সময় সংগৃহীত শব্দগুলোর তালিকায় থাকা সব শব্দ নিয়ে **`Save to Server`** বাটনে ক্লিক করলে সেই সম্পূর্ণ তালিকাটি **একটি পূর্ণাঙ্গ কার্ড** হিসেবে সার্ভারে জমা হয়।
* প্রতিটি কার্ড তার নিজস্ব সংরক্ষণ তারিখ ও সময় (যেমন: `০৫-১১-২০২৬ • ০৪:৩০ PM`) বহন করে এবং কার্ডের ভিতরে সংরক্ষিত সকল শব্দ (অর্থ, পার্ট অফ স্পিচ ও উদাহরণ বাক্য সহ) সাজানো থাকে।
* প্রতিটি কার্ড আলাদাভাবে TXT ফাইল হিসেবে ডাউনলোড করা যায় অথবা কার্ড ডিলিট করা যায়।

### ২. 📊 ওভারভিউতে সিঙ্গেল ও ইউনিক শব্দের গণনা (Overview Word & Unique Stats)
* কার্ডের সংখ্যা যাই হোক না কেন, উপরের ওভারভিউ কার্ডগুলো প্রতিটি শব্দের সংখ্যা হিসেব করে:
  * **মোট শব্দ (Total Words):** সকল কার্ডের মোট শব্দের যোগফল।
  * **ইউনিক শব্দ (Unique Words):** আলাদা আলাদা একক শব্দ (Deduplicated Count) — একই শব্দ একাধিক কার্ডে থাকলে তা একবারই গোনা হয়।
  * **নতুন (New):** নতুন কার্ডের মোট শব্দ সংখ্যা।
  * **রিভিশন (Revision):** রিভিশনে থাকা কার্ডের সকল শব্দের যোগফল।
  * **সম্পন্ন (Done):** পড়া শেষ হওয়া কার্ডের সকল শব্দের যোগফল।
* **কার্ড স্ট্যাটাস টগল (Undo সাপোর্ট সহ):** কোনো কার্ডের নিচে **`🔄 Revision`** বাটনে ক্লিক করলে সেই কার্ডের সকল শব্দ রিভিশন হিসেবে ওভারভিউতে যুক্ত হয়। আবার ক্লিক করলে তা পূর্বের অবস্থায় আনডো (Undo) হয়ে যায়।

### ৩. 📅 সার্চবারে তারিখ লিখে খোঁজার সুবিধা (Date Search: DD-MM & DD-MM-YY)
* সার্চবারে সরাসরি তারিখ লিখে (ইংরেজি বা বাংলা সংখ্যায়) সম্পূর্ণ কার্ড সার্চ করা যায়:
  * যেমন: `10-12` (১০ ডিসেম্বর)
  * অথবা `10-12-26` বা `10-12-2026` (১০ ডিসেম্বর ২০২৬)
  * অথবা বাংলা সংখ্যা `১০-১২` বা `১০-১২-২৬`
* পাশাপাশি যেকোনো ইংরেজি বা বাংলা শব্দ, অর্থ বা বাক্য দিয়েও কার্ড সার্চ করা যায়।

### ৪. ⏱️ সময় অনুযায়ী ফিল্টারিং অপশন (Time-Range Filter)
* ফিল্টার বারে সুবিধাজনক ড্রপডাউন যুক্ত করা হয়েছে:
  * **সব সময় (All Time)**
  * **লাস্ট ৩ দিন (Last 3 Days)**
  * **লাস্ট সপ্তাহ (Last Week / 7 Days)**
  * **লাস্ট মাস (Last Month / 30 Days)**
  * **লাস্ট বছর (Last Year / 365 Days)**
  * এবং নির্দিষ্ট ক্যালেন্ডার তারিখ অনুযায়ী ফিল্টার।

### ৫. ☁️ কন্ডিশনাল সেভ (Conditional Export)
* **`S`** বাটন ওপেন থাকলে বাক্য সহ সেভ হবে; বন্ধ থাকলে বাক্য ছাড়া সেভ হবে।

## 🗄️ ডেটাবেজ কনফিগারেশন: PostgreSQL লিংক কোথায় বসাবেন?

আপনার PostgreSQL ডেটাবেজ সংযোগ স্ট্রিংটি (Connection String) প্রজেক্টের root-এর **`.env`** ফাইলে `DATABASE_URL` নামে বসাতে হবে। `postgressUrl`, `POSTGRES_URL` বা অন্য নাম দিলে এই অ্যাপ সেটি পড়বে না:

### ধাপ ১: `.env` ফাইল খুলুন
প্রজেক্টের রুট ডিরেক্টরিতে `.env` ফাইল তৈরি করুন (বা `.env.example` কপি করে `.env` নাম দিন)।

### ধাপ ২: `DATABASE_URL` ভ্যারিয়েবলে আপনার লিংকটি পেস্ট করুন:
```env
DATABASE_URL="postgresql://username:password@ep-cool-sample.us-east-2.aws.neon.tech/neondb?sslmode=require"
```
*(আপনি Neon.tech, Supabase, Render, Railway, AWS RDS বা স্থানীয় PostgreSQL যেকোনোটির সংযোগ স্ট্রিং ব্যবহার করতে পারেন)*

সংযোগের মানটি পূর্ণ `postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require` URL হতে হবে। `.env.example`-এ placeholder দেওয়া আছে; আপনার provider-এর আসল URL দিয়ে সেটি বদলান।

### ধাপ ৩: ডেটাবেজ স্কিমা পুশ করুন
কমান্ড লাইনে নিচের কমান্ডটি চালান:
```bash
bun run prisma:push
```
এতে `WordCard` এবং `Word` টেবিল তৈরি হবে। `DATABASE_URL`-এ production database দিলে এই কমান্ড সেই database-এর schema পরিবর্তন করবে।

> **বি.দ্র.:** PostgreSQL URL ভুল বা database unreachable হলে API আর JSON ফাইলে সফলভাবে সেভ হয়েছে বলে দেখাবে না। স্থানীয় development-এ URL না থাকলে JSON fallback চলে; Vercel-এর serverless filesystem স্থায়ী নয়, তাই সেখানে `DATABASE_URL` অবশ্যই সেট করুন।

## ❓ পোস্টিং/হোস্টিং সংক্রান্ত তথ্য: GitHub Pages বনাম Vercel / Render

### প্রশ্ন: এটি কি GitHub Pages-এ হোস্ট করা যাবে?
**উত্তর:** 
* **GitHub Pages শুধুমাত্র স্ট্যাটিক ফাইল (Static HTML, CSS, JS) হোস্ট করতে পারে।**
* যেহেতু আপনি এতে **Prisma ORM, Node.js, Express এবং PostgreSQL ডেটাবেজ** যুক্ত করেছেন, তাই ব্যাকএন্ড সার্ভার চালানোর জন্য শুধুমাত্র GitHub Pages যথেষ্ট নয়।
* তবে আপনি চাইলে অ্যাপটিকে খুব সহজে বিনামূল্যে নিচের যেকোনো প্ল্যাটফর্মে হোস্ট করতে পারেন:

| প্ল্যাটফর্ম | খরচ | সুবিধা |
| :--- | :--- | :--- |
| **Render.com** (প্রস্তাবিত) | ফ্রি | Node.js + Express + Prisma সরাসরি সাপোর্ট করে। এক ক্লিকে গিটহাব থেকে ডিপ্লয়। |
| **Railway.app** | ফ্রি টায়ার | PostgreSQL এবং Node.js ব্যাকএন্ড দুটোই একসাথে সহজে চালানো যায়। |
| **Vercel** | ফ্রি | এই repository-তে Vite static build এবং `/api/*` serverless function কনফিগার করা আছে। |

### Vercel-এ deploy
1. Repository-টি Vercel-এ import করুন; Framework Preset `Vite` রাখুন।
2. Vercel Project → **Settings → Environment Variables**-এ `DATABASE_URL` যোগ করুন। Local `.env` ফাইল Vercel-এ upload করবেন না।
3. চাইলে `GEMINI_API_KEY`-ও যোগ করুন। এরপর একটি নতুন deployment দিন।
4. Production database-এর schema তৈরি করতে নিরাপদ জায়গা থেকে `bun run prisma:push` চালান। Command চালানোর environment-এ একই `DATABASE_URL` থাকতে হবে।
5. Deploy হওয়ার পর `/api/status` খুলে `connected: true` এবং `provider: "postgresql"` আছে কি না যাচাই করুন।

### লোকাল মেশিনে চালানোর নিয়ম:
```bash
# ১. ডিপেন্ডেন্সি ইনস্টল করুন
bun install

# ২. প্রিজমা ক্লায়েন্ট তৈরি করুন
bun run prisma:generate

# ৩. ডেটাবেজে টেবিল তৈরি করুন
bun run prisma:push

# ৪. সার্ভার চালু করুন
bun run dev
```
এরপর ব্রাউজারে `http://localhost:3000` লিংকে প্রবেশ করলেই অ্যাপটি চালু হবে। Production build যাচাই করতে `bun run build`, আর production server চালাতে `bun run start` ব্যবহার করুন।
